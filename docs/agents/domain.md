# Domain docs

Use a single-context layout:

- GLOSSARY.md at the repository root.
- Architecture decisions in docs/adr/.

Before exploring a domain, read the glossary and relevant ADRs when present.
If they do not exist, proceed silently. Create them through domain-modeling
when terminology or architectural decisions are actually resolved.

Use glossary terms consistently in code, tests, issues and proposals.
Surface conflicts with existing ADRs explicitly before proposing a change.
